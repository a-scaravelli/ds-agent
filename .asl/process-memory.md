The branch already had earlier commits for this ticket; this round added the documentation, the design/README tests and the test map.
- **Decisioni**: libraries judged on the criteria of section 1 (Mac without GPU, free, offline, low maintenance, reproducible with a seed). pandas + numpy + scikit-learn chosen (confirmed by the user): the metrics and partition primitives are well tested and deterministic for a seed. Rejected: pure Python (error-prone ties, stratification, edge cases, no benefit), polars/pyarrow (further from the stack of generated code and Kaggle notebooks, no need shown), scipy alone (statistics but no ready partitioning or metrics). LightGBM and MLflow left out of this ticket. Threshold: one parametric form, mean paired difference oriented by the metric direction must exceed `k` × sample standard deviation (ddof=1) of the baseline over all partitions; `k` comes from the protocol, no default; comparisons are stored and counted but the threshold does not grow with the count yet. Protocol hash: protocol content plus SHA-256 of the `.py` sources of `evaluation`, computed at runtime (no manual version constant), stored on the cycle at `freeze()` and rechecked before every evaluation and holdout read; library versions are outside the hash and recorded in `resources`. Metric and scheme never have a default; the direction is explicit in the protocol and only checked against the one declared by the metric. Deterministic schemes accept repetitions: identical folds, only the candidate seed changes, so the baseline dispersion measures model-seed noise. Holdout: one session per cycle (best attempt plus user-requested variants), each read logged in the registry before the data is returned, one read per attempt, no reopening even after closing, a failed evaluation still consumes the session. To reconfirm: a candidate exception that leaves the session block makes the remaining variants unevaluable in that cycle (the caller must handle errors inside the block if it wants otherwise); the engine does not check that the attempt read is the best one (left to report/review, ticket 10). Known limits: the holdout guarantee is interface plus log only, real isolation comes with the sandbox (ticket 6); the hash depends on the bytes of the sources, so any edit of the package (even a reformat or different line endings) invalidates the frozen protocols of open cycles, and a library change in the middle of a cycle is recorded but not blocked; session rules read-then-write are safe for a single process only. The engine returns the execution record but does not persist it (the loop ticket does, and must also call `freeze()` at approval). No defect found in the code.
